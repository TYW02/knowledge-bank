Heap Files (Random Order)

Records are placed without any specific ordering. Finding a record requires scanning all pages (full table scan).

Sorted Files

Records are maintained in sorted order by a search key. Ideal for order-sensitive retrieval, binary search, and range scans.

Indexes

Auxiliary data structures built alongside data files containing search keys and page pointers to jump directly to target data pages.

2.1 Core Concepts: Buckets & Hash Function h(r)

Primary + Overflow Pages

Buckets (Primary Page + Overflow Pages)

A hash index consists of a collection of buckets. Each bucket is composed of one primary page plus zero or more linked overflow pages storing data entries when a bucket fills up.

Deterministic Hash Function h(r)

A fixed mathematical function applied to the search key fields of record r that computes the exact target bucket ID (h(r) = bucket). The exact same hash function is used for all records.

2.3 Key Revision Questions & Hash Properties

Exam Essentials

Q1: Can two records be in the same bucket?

YES. Records with identical search key values (e.g., all 4 Stark records) or distinct keys that hash to the same bucket ID (hash collision) share the same bucket.

Q2: Can one record be in different buckets?

NO. The hash function h(r) is strictly deterministic and maps a given search key to one and only one bucket.

Q3: Equality Search vs. Range Search?

Equality Search ONLY ($O(1)$). Hash indexes are not suitable for range search because hash functions scatter adjacent keys randomly across uncorrelated buckets without preserving sort order.
