1.2 The Concurrency Problem in Multi-User Environments

Order & Throughput

1. Shared Data Access

Multiple users or threads execute transactions simultaneously on a shared database, accessing and modifying overlapping records.

2. Execution Order Sensitivity

The final database state and computed balances directly depend on the execution order (interleaving) of read/write operations across threads.

3. System Throughput Trade-off

Strict one-at-a-time execution is safe but slow; system throughput improves dramatically when non-conflicting operations are scheduled concurrently.

2.3 Schedule Terminology

Core Definitions

Serial Schedule

A schedule that does not interleave operations of different transactions. Provides the highest safety level, but poor efficiency and low throughput.

Equivalent Schedule

Two schedules that produce the exact same output for any initial database state.

Serializable Schedule

An interleaved schedule whose output is equivalent to the output of some serial execution (either Order 1 or Order 2).

4.3 Three Ways a Transaction Ends in SQL

Boundary Rules

1. Explicit TCL Command

An explicit COMMIT (makes pending changes permanent) or ROLLBACK (discards all pending modifications).

2. DDL or Privilege Statements

Execution of Data Definition Language statements (CREATE, ALTER, DROP) or access control commands (GRANT, REVOKE) implicitly ends/commits the active transaction.

3. Program Termination

Normal/natural program termination or clean application exit concludes the transaction.

5.1 & 5.2 Failure Taxonomy, Prevention & Recovery Tiers

Checkpoints vs. Secondary Devices

1. Prevention ("Best Defense")

Hardened Linux server OS, strict local network security, and Uninterruptible Power Supply (UPS) to prevent power/cyber outages.

2. Physical Media Working

After a system crash or power loss where disks remain intact, the DBMS uses checkpoints and the Transaction Log to restart and redo committed transactions.

3. Physical Media / Disk Damage

When disk drives or transaction logs are physically corrupted, restore from periodic backups stored on secondary devices (e.g., magnetic tape).

Topic 7 // Lock-Free Concurrency Control

Optimistic Concurrency Control (3-Phase Method)

Understand why optimistic concurrency eliminates lock overhead for read-heavy workloads and simulate Read, Validation, and Write phases under both passing and conflicting outcomes.

Lock-Free 3 Phases

7.1 Interactive 3-Phase Optimistic Method Simulator

Phase 1: Read Phase

Transaction reads data items and keeps a private data copy. All updates are written to a private, temporary workspace without acquiring locks.

Phase 2: Validation Phase

Before committing, the DBMS checks whether concurrent transactions modified the same items and violated consistency.

Phase 3: Write Phase

If validation passes, private updates are written permanently to the database. If validation fails, the transaction aborts and restarts cleanly.
