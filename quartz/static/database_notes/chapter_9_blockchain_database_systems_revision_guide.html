1.3 Three Core Pillars of Blockchain Systems

Architectural Summary

1. Chronological Encryption Blocks

Transactions are bundled into encryption-based blocks and chained chronologically from old to new. Every full node stores an identical copy of the entire ledger history.

2. Equal Distributed Authority

Unlike centralized institutions (e.g., OCBC Bank) that hold unilateral authority, every participant node in a distributed ledger holds the truth and has an equal say in state validation.

3. Consensus Protocols

Network-wide agreement mechanisms replace central authorities with distributed governance, enabling untrusted nodes to agree on the single valid transaction history.

Why package multiple transactions into one block? Creating 1 block per transaction would create an impractically long chain. Miners select pending broadcast transactions from the mempool—prioritizing higher transaction fees to maximize earnings!

Pending P2P Mempool (Signed Broadcast TXNs):

Three-Stage Transaction & Block Creation Summary

End-to-End Flow

Stage 1: Initiation & Digital Signature

User encrypts transaction details with a digital signature (analogous to signing a physical check) to prove authenticity, then broadcasts it across the P2P network.

Stage 2: Packaging & Fee Incentives

Nodes bundle multiple signed transactions into a single block (preventing an impractically long chain), prioritizing transactions offering higher user-attached fees.

Stage 3: Mining Competition & Rewards

Nodes compete simultaneously to append the next single block. The winner earns block rewards (newly minted coins) plus all collected transaction fees.

4.2 Lecture Math: Target < 2200

A SHA-256 output is 256 bits. Requiring hash < 2200 means the first 56 binary digits (256 - 200 = 56) must all be 0 (000...0). Since each bit has a 50% chance of being 0, finding a valid nonce requires an expected 256 trial attempts—preventing cheap Raspberry Pi / MCU spam attacks!

6.2 Physical World Traceability Bottleneck

On-chain digital immutability cannot guarantee physical-world authenticity. For example, recording organic food certificates on a blockchain cannot prevent physical packaging tampering or product swapping in physical supply chains.

6.3 Suitable Enterprise & Financial Use Cases

Where Blockchain Excels

1. Universal Borderless Currency

Facilitates direct peer-to-peer international value transfers without traditional bank remittance delays or SWIFT codes (note: also misused in dark/black markets due to pseudonymity).

2. Anti-Counterfeiting & Tamper-Proof Document Verification

Ideal for digital authenticity where any unauthorized modification must be detected instantly via hash comparison—such as patents and cross-border COVID-19 medical certifications.
