1.1 Relational Database Strengths & Centralized Architecture Trade-Offs

ACID & SQL

Core RDBMS Advantages

  • Strict transactional integrity (ACID).
  • Robust concurrency control & automated recovery.
  • Solid mathematical foundation (relational algebra & set theory).
  • Standardized SQL & mature tool ecosystem.

Pros of Centralization (Single Node)

  • Fast local table joins in memory/disk.
  • Simpler administration and configuration.
  • Straightforward single-point transaction processing.

Cons of Centralization

  • Single point of failure.
  • Severe hardware resource ceilings (CPU/RAM/Disk).
  • Difficult to partition or distribute across geographic regions.

2.1 Definition & Philosophical Goals

Generalizability & Availability

What Does "NoSQL" Stand For?

Not Only SQL (also referred to as Non-SQL, Neo SQL, or No SQL). It complements relational databases rather than replacing them universally.

Primary Philosophical Objective

Simplify data models to improve generalizability and efficiently handle diverse unstructured/semi-structured data formats, high availability, and geo-distributed nodes.

5.1 & 5.2 Row-Wise (MySQL) vs. Column-Wise (Cassandra) Disk Storage

Relational Row-Wise Disk Layout (e.g., MySQL)

Stores full records contiguously; reading 1 column forces reading entire rows:

Columnar Disk Layout (e.g., Cassandra)

Stores all values of each column contiguously (high compression + fast column scans):

3-Part Key Structure: (Row Key, Column Key, Timestamp)

Every cell is addressed by Row Key, Column Key, and a Timestamp used for data versioning, conflict resolution, and history tracking across distributed nodes.

Strengths vs. Write Trade-Off

Strengths: High compression (identical types stored together), self-indexing, fast analytical reads.
Weakness: Inserting a full multi-column row is slower because values are split across multiple column blocks on disk.

1. Node

Represents entities (e.g., Alice, Tom Hanks, Dept). Stores properties and direct pointers to adjacent edges.

2. Label

Classifies or groups nodes into types (e.g., :Person, :Department, :Movie).

3. Relationship

Directed link connecting two nodes with a specific Type (e.g., :BELONGS_TO, :ACTED_IN, :DIRECTED) and properties.

Named key-value pairs on nodes or relationships (e.g., name: 'Tom Hanks', roles: ['Forrest']).

Topic 7: Three SQL-to-NoSQL Migration Strategies

Effort vs. Performance

Scheme 1: 1-to-1 Mapping (Most Popular)

Method: Map 1 SQL table directly to 1 NoSQL collection (e.g., MongoDB).
Tools: AWS DMS, Python scripts, SQL Server Export.
Result: Easiest implementation with minimal architectural redesign.

Scheme 2: Denormalization

Method: Reverse normalization by combining small relational tables back into consolidated, nested documents.
Result: Moderate refactoring effort with moderate read performance improvements.

Scheme 3: Design from Scratch

Method: Discard legacy relational schemas and completely re-architect the data model around NoSQL query patterns.
Result: High initial effort, but yields optimal long-term performance and scalability.
