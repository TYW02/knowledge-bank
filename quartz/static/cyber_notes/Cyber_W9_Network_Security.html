1 · Network Fundamentals & Threat Modelling

Before attacking or defending anything, you need a model: what a network is, how data is layered, and what "risk" actually means.

Computer network — definition

A system of interconnected autonomous computers, people, or devices exchanging information, resources or services over copper wire, fibre optics, microwaves, infrared, or communication satellites.

Categories: computer networks, social networks, infrastructure networks, broadcasting networks.

1.1 Encapsulation hierarchy

Data is crafted and processed hierarchically. At every layer the payload gets a new header prepended — by the time it reaches the wire, the original application data sits inside four nested envelopes.

Link Layer Frame header + MAC addresses + trailer
Internet Layer IP header — source & destination IP
Transport Layer TCP / UDP header — ports & sequence numbers
Application Layer HTTP request, DNS query, credentials…

Application → Transport → Internet → Link   |   each step prepends a header

2 · Denial of Service (DoS) & DDoS

Availability attacks: you don't need to steal anything if you can simply stop the service from working.

Definitions

DoS — attacks designed to disrupt or take down the availability of a system or network asset. Tool example: High Orbit Ion Cannon (HOIC).

DDoS — the same, but launched from many distributed sources (botnet) rather than one host.

2.1 Three attack classifications

1 Bandwidth flood

Overwhelm the target's physical or logical network capacity — e.g. sending 150 MB/s at a pipe with only 100 MB/s capacity.

2 Service request flood

Exhaust compute/memory with high volumes of anomalous HTTP requests, DNS queries or TCP connection requests. Requests do not need to succeed to consume resources.

3 SYN flood

Exploit the TCP 3-way handshake: flood continuous SYN packets, fill the server's connection queue (TCP Queue Full) while ignoring SYN-ACK replies.

3 · Man-in-the-Middle & Wireless Access Point Exploits

Wireless is an open radio medium — anyone nearby can listen, and anyone can pretend to be the access point.

Why wireless is different

Open radio mediums allow any nearby device to attempt access or eavesdrop on unencrypted management traffic. There is no physical cable to control access to.

Wardriving

Physically moving through an area with portable hardware/laptops to map, locate and assess Wi-Fi Access Points for potential vulnerabilities.

Evil Twin

Deploying a rogue Wi-Fi Access Point configured with the identical SSID (Service Set Identifier) of a legitimate network — e.g. both broadcast SIT-WIFI — to intercept wireless communications.

4 · Network Sniffing & Traffic Analysis

Sniffing is just listening — the attack works because the traffic was never encrypted in the first place.

Packet sniffing

Intercepting raw network packets traversing a wire or wireless link. Transmitting unencrypted traffic leads to direct privacy loss — harvesting passwords, credit card data and private messages.

4.1 Hub vs switched network — the architecture that decides your technique

Hub — passive sniffing

All incoming packets are broadcast to every physical port. An attacker just puts the NIC into promiscuous mode and sees everything.

Highly stealthy and difficult to detect — but useless on a switch.

Switch — active sniffing

Switches isolate traffic using internal MAC address tables, so the attacker sees nothing by default.

Sniffing requires injecting malicious traffic — e.g. ARP spoofing via arpspoof — to force other nodes' traffic through the attacker's NIC.

Sniffing software: Wireshark, Cain and Abel.

5 · Spoofing, Poisoning & Deep Packet Inspection

ARP has no authentication. That single design decision underpins most local-network MitM attacks.

5.1 ARP and ARP poisoning

What ARP does

The Address Resolution Protocol translates 32-bit Internet Layer IP addresses into 48-bit Link Layer physical MAC addresses — e.g. IP 192.168.174.100 → MAC 00:00:5e:00:53:af.

Stateless vulnerability

ARP has no verification or authentication mechanism. Requests and replies can be freely forged by anyone on the segment.

ARP cache

Operating systems maintain local lookup tables mapping IP addresses to MAC addresses. The cache is consulted before every outbound frame.

Watch a victim's ARP cache get poisoned

Victim ARP cache — before
192.168.174.100:11:22:33:44:01  (gateway)
192.168.174.10000:00:5e:00:53:af
Victim ARP cache — after poisoning
192.168.174.100:11:22:33:44:01  (gateway)
192.168.174.10000:00:5e:00:53:af

Mechanism in one sentence

The attacker sends forged, unsolicited ARP replies to the victim, updating its ARP cache so that the default gateway's IP maps to the attacker's MAC address. Every outbound packet now goes to the attacker first.

5.2 Port spoofing & firewall evasion

Bypass perimeter firewall rules by encapsulating malicious protocol traffic (SSH remote access, malware transport) over allowed web ports like HTTPS (443) instead of blocked standard ports (SSH 22).

ssh -L 8443:serverA:443 -Nf [user@]serverB
Attacker / clientwants SSH into serverA
Perimeter firewall ✗ port 22 → BLOCKED
✓ port 443 → ALLOWED
serverA : 443receives the tunnel
Payload on the wire: [ TCP dst port 443 ][ SSH protocol inside ]

The blind spot

Standard packet-filtering firewalls inspecting only transport/IP headers see dst port 443 and allow it. They fail to detect the hidden SSH tunnel inside.

5.3 Deep Packet Inspection (DPI)

How DPI fixes it

DPI is an advanced filtering mechanism that examines both packet headers AND payload contents/code. Through application intelligence it identifies the faux-HTTPS traffic as SSH protocol and routes it to security tools for blocking or decryption — overcoming the header-only limitation.

Filtering typeInspectsDetects SSH-over-443?
Packet filtering (header only)IP / TCP / UDP headers✗ No — sees only port 443
Deep Packet InspectionHeaders and payload contents✓ Yes — protocol fingerprinting

6 · Port Scanning & Reconnaissance Methodology

Recon maps the attack surface before a single exploit is fired.

Definition

Probing a target host's ports (e.g. 21 FTP, 25 SMTP, 80 HTTP, 443 HTTPS) to identify which services are open, closed, or filtered.

6.1 Port states

open

A service is actively accepting connections on that port.

closed

The port is reachable but no service is listening — the host replies with RST.

filtered

A firewall drops the probe — no response at all, so Nmap cannot tell open from closed.

Scan typeBehaviourStealth
TCP Connect scan (-sT)Completes the full 3-way handshake, then tears it down.Loud — logged by the application
SYN stealth scan (-sS)Sends SYN, reads SYN-ACK, then immediately sends RST. Never completes the handshake.Quieter — often not logged · Nmap default
