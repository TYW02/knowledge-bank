1 · Digital Forensics — Fundamentals & Process Models

Forensics is science applied to legal problems. Digital forensics is that science aimed at evidence stored or transmitted on digital devices.

Definitions

Forensics — the application of science to legal problems and investigations.

Digital Forensics — the branch of forensics involving the recovery and investigation of digital evidence stored or transmitted using digital devices.

Forensic domains

  • Computer forensics
  • Storage forensics
  • Network forensics
  • Mobile forensics

Categories of digital evidence

Emails · credit card transactions · accounting files · notes · images · internet browsing history · IP addresses · system logs · malware payloads.

1.2 Evidence integrity — chain of custody & cryptographic hashing

Chain of custody

Demonstrating that the evidence analysed and presented in court is identical to what was collected at the scene without tampering. Cryptographic hashing is how that claim is proven: a unique checksum is generated on acquisition and re-computed later. Any collision or alteration invalidates evidence integrity.

MD5 (legacy)  →  SHA-1  →  SHA-2 (SHA-256)

Live demo — edit the evidence and watch the hashes break

Why this matters in court

If the SHA-256 of the acquired image and the SHA-256 of the analysed copy disagree, the defence can argue the evidence was altered in custody — and it becomes inadmissible. Hashing is not administrative paperwork; it is the evidentiary foundation.

2 · OS Forensics & Evidentiary Artefacts

The operating system supervises every state change triggered by a user — human or bot. Those state changes leave artefacts.

What the OS records

File downloads · program executions · file creation / modification / deletion · physical device connections · USB storage attachments · user account activity · network usage.

2.1 Volatile memory vs persistent storage

RAM — volatile

  • OS loading — bootloader code and data
  • OS initialisation — service processes, shared libraries, kernel in-memory data structures
  • User session(s) — active application process state and memory buffers

ROM / disk — persistent

Persistent bootloader code, kernel binaries, system configurations, service executables, log files, temporary files, app executables, configuration files, user data files.

Forensic consequence: RAM must be captured first — power loss destroys it forever. Disk survives a reboot.

2.4 Linux forensics artefacts

Key characteristics

  • No centralised registry — system info is scattered across plain-text files.
  • Different file systems — traditionally no file creation timestamps before EXT4.
  • Plain-text data enables fast string searching (grep, strings).

Credential files

  • /etc/passwd — basic account info; UID 0 = root.
  • /etc/shadow — encrypted password hashes; cracked offline with tools like John the Ripper.
  • /etc/group — group memberships.
  • /etc/sudoers, /etc/inittab, /var/spool/cron/* — privilege and scheduled-task persistence.

Log files

  • /var/log/wtmp — login history (user, source IP, login time, session duration), read with the last command.
  • /var/log/auth.log / /var/log/secure — authentication attempts.
  • /var/log/boot.log, /var/log/audit/audit.log.

4 · Defense-in-Depth & Security Strategy

No single wall stops an attacker. Layers delay, detect and contain — buying time and forcing mistakes.

Concept

Implementing layered security controls across multiple system levels to delay and stall an attacker's progress, rather than relying on a single boundary barrier.

5.2 Firewall mitigations & limitations

Effective against

  • Port scanning — locks down unused ports.
  • Unauthorised IP access — wardriving mitigation.
  • Simple connection floods.

Limitations

  • Ineffective against complex reflection DDoS — attackers spoof victim IPs to make vulnerable Memcached servers reflect massive UDP responses.
  • Cannot block malicious traffic traversing authorised open ports (e.g. HTTP 80).
  • Helpless against perimeter bypasses — e.g. an unauthorised dial-up modem inside the internal network.

5.3 Firewall rule logic — the source-port flaw

A firewall rule evaluates protocol, source IP/port, destination IP/port, and action (Allow / Deny). Try the tester below with different client source ports.

❌ Bad rule
TCP | SRC Any : 80 | DST 24.180.49.139 : 80 | DENY

Outbound client web requests originate from dynamic ephemeral ports 1024–65535, so malicious HTTP on a non-80 source port bypasses this rule.

✔ Good rule
TCP | SRC Any : Any | DST 24.180.49.139 : 80 | DENY

Correctly blocks all TCP traffic destined for port 80 regardless of the client's source port.

5.4 Stateless vs stateful filtering

Internal client:52341
Web server:80

Stateless packet filter

Evaluates each packet in isolation against ACLs, with no connection context. Return traffic must be explicitly permitted by another rule. Example: extended ACLs on Cisco IOS routers.

Stateful packet filter

Maintains a dynamic state table tracking handshakes and connection states (SYN, ESTABLISHED). Automatically permits return traffic for legitimate outbound sessions. Example: Cisco ASA/PIX, Check Point.

6 · Intrusion Detection (IDS) & Prevention (IPS)

IDS watches and alerts. IPS sits in the path and acts. The difference is inline vs out-of-band.

Internetattack source
Firewallboundary
Internal networkprotected assets

NIDS — Network Intrusion Detection System

  • Monitors traffic out-of-band — not in the inline path.
  • Deployed on a hub (promiscuous mode) or a switch SPAN port (port mirroring).
  • Supported by Host IDS (HIDS) agents on endpoints.
  • Uses Deep Packet Inspection (DPI) on payloads.
  • Detection methods: signature-based (known patterns) or statistical anomaly-based (deviations from baseline).

NIPS — Network Intrusion Prevention System

  • Placed inline between the firewall and the internal network.
  • Performs full NIDS detection plus active automated remediation.
  • Drops malicious packets.
  • Resets TCP connections (RST).
  • Dynamically modifies firewall rule sets in real time.

7 · Proxies & Virtual Private Networks

Proxies break direct routing; VPNs build encrypted tunnels over untrusted networks.

7.1 Application proxy / proxy firewall

Layer 7 operation

Operates at the Application Layer of the OSI model. It terminates the incoming client connection and establishes a secondary connection to the destination server on the client's behalf — eliminating direct IP routing between external users and internal servers.

External clientno direct route to server
Proxy (L7)terminates + re-originates
Internal serveronly sees the proxy
client ──TCP──▶ proxy ──TCP──▶ server   (two separate connections)

DPI & content inspection capabilities

Scans protocol-specific traffic (HTTP, HTTPS, FTP, SMTP) and inspects payloads to:

  • Block prohibited file extensions
  • Detect domain spoofing
  • Enforce content policies
  • Provide IP anonymisation
  • Cache frequently accessed pages to optimise performance

Example products: Symantec Advanced Security, Gateway ProxySG.

7.2 VPNs — IPsec vs TLS

A VPN establishes an encrypted tunnel across an untrusted public network (the internet), ensuring data confidentiality, integrity and origin authenticity.

Feature / metricIPsec VPN (L2TP / IPsec)TLS VPN (OpenVPN)
OSI layerNetwork / Link (Layer 3 / 2)Transport / Application (Layer 4 / 7)
Protocol mechanicsPairs L2TP with IPsecOpen-source TLS for key exchange & transport
Encryption256-bit AES160-bit to 256-bit AES
Performance overheadDouble encapsulation — higher CPU overheadOptimised for high-latency networks
OS compatibilityNative on Windows, macOS, Linux, iOS, AndroidCompatible across desktop & mobile platforms

8 · Switch Port Security & the AAA Framework

Switches learn MAC addresses dynamically — which means an attacker can teach them wrong.

8.1 MAC learning & MAC flooding

Dynamic MAC learning

Switches inspect incoming Ethernet frame source MAC addresses to build dynamic MAC tables. Unmapped destination MACs trigger frame flooding to all ports.

MAC flooding attack

Attackers flood a switch with thousands of fake MAC addresses, exhausting memory tables and forcing the switch into fail-open hub mode — broadcasting all traffic and enabling passive sniffing.

8.2 Switch port security mitigations

Restrict MAC count

Limit the maximum number of MAC addresses allowed per physical port.

Bind static MACs

Bind specific MAC addresses to specific physical ports so a rogue device cannot impersonate another.

802.1X NAC

Enforce Network Access Control — devices must authenticate before the port passes any traffic.
