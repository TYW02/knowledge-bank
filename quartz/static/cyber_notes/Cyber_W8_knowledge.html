1 · Fundamentals of Malicious Software

What malware is, why it targets specific platforms, and the four dimensions of organisational impact.

Core definition

Malware is any software program intentionally engineered to intrude into a system without user authorisation, degrade system performance, alter stored data, or disrupt service availability.

1.1 Platform dependence

  • OS-specific targeting — malware often relies on detailed operational knowledge of a host OS: default configurations, file permission models (Unix permissions), or privilege structures (Windows admin rights).
  • Cross-platform malware — compiled to run on multiple operating systems by abusing platform-agnostic execution environments such as the Java Virtual Machine.

Slide example Adwind — cross-platform Java Trojan

Adwind is written in Java and therefore runs anywhere a JVM exists. On macOS it achieves persistence by:

  • Dropping a Java applet named BgHSYtccjkN.ELbrtQ inside a dot-prefixed hidden directory in the user's home folder (~/.UQnxIJkKPii/…). Dot-prefixed paths are hidden from Finder by default.
  • Registering an XML Property List (.plist) launch agent containing <key>RunAtLoad</key><true/>, so the payload auto-runs at system boot.

1.2 Impact taxonomy — four organisational dimensions

Impact dimensionMechanism & consequencesConcrete example
DataUnauthorised alteration, deletion, encryption or exfiltration of sensitive files.Harvesting stored user credentials; modifying confidential database entries.
TimeRendering core system functionality unusable; operational downtime until cleanup.System crashes or resource exhaustion stopping legitimate users from working.
HardwareIndirect physical or functional damage by corrupting low-level system software.Corrupting device drivers or device firmware, disabling hardware components.
ReputationLoss of commercial confidence, public embarrassment, direct financial damage.Exfiltrating private corporate emails or customer records and leaking them publicly.

2 · Viruses — Mutation, Insertion & Anatomy

Viruses are the only major malware class that fundamentally requires a human being to press the button.

2.1 Core characteristics

Human interaction required

A virus cannot self-replicate automatically across networks. It spreads only when a user executes an infected file, opens an infected script, or plugs in infected media.

Host program attachment

Viruses attach to legitimate host files or shell scripts. Supported hosts include Windows .exe binaries, Unix shell scripts (.sh), and Windows batch files (.bat).

Infection flags / markers

After infecting a file, the virus writes a unique marker into the host header or binary structure, signalling "already compromised" and preventing infinite reinfection loops.

Why mutation matters

Signature-based antivirus matches byte patterns. If the bytes change on every infection, the signature library is always one step behind.

VariantMechanismEffect on AV
Metamorphic
mutating		 Alters its underlying code structure, instruction sequences and binary appearance on every infection cycle, while keeping the functional payload intact. No stable byte signature to match — the file looks different each time.
Polymorphic
encrypted		 Encrypts its main payload with a unique key per infection and pairs it with a varying decryption routine. The ciphertext changes; only the decryption stub may stay recognisable.

2.2 Virus insertion mechanics — interactive

Click each technique to see how the virus lays itself out inside (or beside) the host file.

Why "Companion" is sneaky

The host binary is completely unmodified — its hash, size and signature all still look clean. The virus simply creates a second executable with the same base name or a higher-priority extension (e.g. prog.com alongside prog.exe), and Windows executes the .com first.

2.3 Virus anatomy — three functional code segments

1 · Concealment

Routines engineered to bypass security controls, obscure code signatures, and hide from antivirus scanners.

2 · Propagation

Routines that scan host storage, identify uninfected candidate files, and place infection markers.

3 · Payload

Non-propagation code designed to execute the malicious action — corrupting storage, exfiltrating data, etc. The payload is often dormant until a trigger fires.

2.4 Activation triggers

Logic bomb

Payload executes when a specific system event or condition occurs — e.g. an administrator account being deleted, a particular file appearing, or a certain user logging in.

Time bomb

Payload executes when the system clock reaches a specific date or time.

Slide example — Windows batch-script time bomb:

If "%date%" NEQ "Thu 01/09/2016" goto exit
REM format E: /y >nul
echo "Hello World!"
:exit

On every run the script compares the system date. If it is not 1 September 2016, it jumps straight to :exit. Once the date matches, control falls through to the destructive line and reformats drive E: — silently, because output is redirected to nul.

3 · Worms — Autonomous Propagation

A worm is malware that needs no human and no host file — it is a self-driving network threat.

3.1 Core characteristics

  • Autonomous replication — no human interaction, no host document to attach to. The worm actively scans networks, exploits unpatched services and self-replicates.
  • Carrier & payload — the worm is often just the delivery vehicle; it drops secondary attack tools, backdoors or botnet clients onto each victim.

Primary propagation mechanisms

VectorHow it works
Windows administrative sharesSpreads over SMB by leveraging open admin shares (net share).
Unix remote shell scriptsExecutes commands across remote Unix systems via legacy protocols such as rsh.
Networking software vulnerabilitiesExploits flaws in network services — e.g. Stuxnet abused the print spooler.
Password crackingAutomated brute-forcing of weak SSH / administrative credentials — the Morris Worm did exactly this.

3.2 Historical milestones

WormYearSignificance
Morris Worm1988Earliest recognised internet worm; propagated via rsh, network bugs and automated password cracking.
Blaster2003Targeted Microsoft RPC buffer overflow vulnerabilities.
Conficker2008Built massive global botnets by exploiting SMB weaknesses.
Stuxnet2010Cyber-weapon using Windows zero-days and print-spooler flaws to reach industrial control systems.
SMB Worm ToolDec 2014Automated exploitation tool targeting SMB protocols.
EternalRocks2017–18Multi-exploit SMB worm; silently infects and drops persistent backdoors for future C2 operations.

3.3 Case study — Ikee / Duh (Ikee.B) smartphone worm

  • Target: jailbroken iPhones running iOS with default OpenSSH installed.
  • Infection: scanned IP ranges for port 22 open, logged in with the default credentials root / alpine, then changed the SSH password to lock the real owner out.
  • C2: recruited victims into a mobile botnet controlled from a command centre in Lithuania.
  • Payload: exfiltrated contacts, SMS messages and financial data to an external attacker database.

Lesson: a worm needs no user action — only a reachable service and a default credential.

4 · Trojans, Keyloggers, Backdoors & Netcat

Trojans earn initial access by deception; the backdoor they install keeps it.

Trojan horse

A program disguised inside seemingly harmless software (a fake utility, a "free" game crack). Trojans do not self-replicate. They establish backdoors, install RATs and keyloggers, and can grant remote webcam and system control.

Keylogger

Surveillance software that intercepts and records physical keystrokes. Harvests plaintext passwords, login credentials, private emails, credit card numbers and financial details. Slide tool: Spyrix Free Keylogger.

Backdoors & RATs

Remote administration utilities configured for persistent, unauthorised access — examples include Netcat (nc) and ProRAT. Note that Netcat is explicitly flagged as a malicious binary by standard AV and by university IT policy (CIT): it is a legitimate tool that is overwhelmingly used illegitimately in this context.

6 · System Architecture & Cross-Layer Threat Model

    
Security vulnerabilities routinely cross structural layer boundaries.


    

      
Von Neumann architecture

      
A computing system = hardware components combined with system software executing userland applications. Critically, exploits frequently cross layer boundaries — for example, leaking speculative CPU microarchitectural state back into userland software memory (Spectre). A security specialist must understand full-stack execution, not just one layer.

7 · Hardware & Microarchitectural Attacks

    
When the silicon itself is the vulnerability, software patches can only mitigate — never cure.


    
7.1 Three hardware attack classes

    

      
Counterfeit attacks
Distribution of tampered hardware components (manufacturing-stage hardware Trojans with built-in backdoors), or dropping malicious USB drives that emulate Human Interface Devices (HID) and inject keystrokes.

      
Micro-architectural attacks
Targeting CPU implementation details — speculative execution side-channels, DRAM hardware vulnerabilities.

    

    
Fault injection attacks
Physical tampering to alter instruction execution within integrated circuits.


    
7.2 Four fault-injection techniques compared

    

      

        
TechniqueAbbr.Sample access requiredMechanism

        
          
Power/Clock Glitch Fault InjectionPGFIPin access only (non-invasive)Voltage or clock-frequency glitches injected into external IC pins.

          
Light/Laser Fault InjectionLFIFront-side / back-side depackaging requiredTargeted optical laser pulses onto the exposed silicon die.

          
Electromagnetic Fault InjectionEMFIFront-side / back-side partial depackagingLocalised periodic EM pulses near the chip surface.

          
Body Biased Fault InjectionBBFIBack-side depackaging requiredBias voltage applied directly to the silicon substrate from the rear.

        
      

    


    
7.3 Case study — Spectre (CVE-2017-5753 / CVE-2017-5715)

    

      
Root cause

      
Spectre exploits speculative execution, a performance optimisation. When the CPU hits a conditional branch whose operand is in slow DRAM, it predicts the branch and executes ahead. If the prediction is wrong it rolls back the architectural state — but leaves microarchitectural cache modifications intact. That residue is the leak.

    


    
Lecture code:


#define PAGESIZE 4096
unsigned char array1[16];
unsigned int  array1_size = 16;
int x;                          /* out-of-bounds index, attacker controlled */
unsigned char array2[256 * PAGESIZE];   /* timing side-channel instrument */
unsigned char y;

if (x < array1_size) {
    y = array2[array1[x] * PAGESIZE];
}


    
Step through the exploit

    

      

      

        
array1[16]

        

        
array2[256 × 4096]  —  256 cache lines

        

      

      

      

        
      

    


    

      
Remediation reality

      
Because Spectre targets a fundamental hardware performance feature, no simple software patch removes the root cause. Mitigation requires extensive OS and compiler-level hardening (retpolines, array index masking, cache flushing barriers) — and costs performance.

    

  


  
  

    
8 · Software & Control-Flow Attacks

    
Code injection and command injection both boil down to the same failure: untrusted data being treated as instructions.


    
8.1 Control-flow hijacking

    

      

        
Stack smashing

        
Overwriting stack memory buffers to replace a function's return address with an address pointing at injected shellcode.

      

      

        
Return-Oriented Programming (ROP)

        
Chaining together small existing snippets (gadgets) ending in ret inside legitimate system binaries — bypassing Write-XOR-Execute (W ⊕ X) memory protections because no new code is ever written.

      

    


    

      
Code injection vs command injection

      
Code injection: malicious input is supplied to a generator program, which produces executable code consumed and run by an executor program.

      
Command injection: a specialised subcategory where unvalidated user input is passed directly into an OS command interpreter shell (/bin/sh or cmd.exe).

    


    
8.2 The vulnerable C program from the slides


#include <string.h>
#include <stdlib.h>

int main(int argc, char* argv[])
{
    for (int i = 1; i < argc; i++) {
        char cmd[256] = "/usr/bin/cat ";
        strncat(cmd, argv[i], sizeof(cmd) - strlen(cmd) - 1);
        system(cmd);
    }
    return 0;
}


    
Flaw: strncat() correctly bounds the string length — there is no buffer overflow here. But it does not sanitise shell metacharacters (;, |, &, $(), backticks). Whatever survives goes straight into system(), which hands it to /bin/sh.


    
8.3 Try the exploit — interactive

    

      
      
      

    


    

      
Remediation

      
Avoid invoking a command interpreter through system(). Instead, sanitise/allow-list inputs strictly, or execute the binary directly with execve() and pass the filename as an argument vector element — the shell then never parses the metacharacters at all.

    

  


  
  

    
9 · Hypervisor Architecture & Virtualisation Vulnerabilities

    
Virtualisation adds a layer — and a new attack surface that sits below the guest OS.


    
9.1 Three hypervisor models

    

    

    


    
9.2 Virtualisation attack categories

    

      
Hyperjacking

      
Replacing or inserting a rogue, malicious hypervisor underneath or alongside the legitimate one. Because the rogue hypervisor runs at a lower layer than the guest OS, its presence is virtually impossible to detect from inside the OS.

    

    

      
Virtual Machine Rootkit

      
A specialised hyperjacking attack where a rootkit running underneath the OS spawns invisible separate virtual machines to execute hidden malware operations.

    

    

      
Virtual Machine Escape

      
An exploit that breaks the hypervisor's isolation boundary, letting a process inside a guest VM execute arbitrary code directly on the host OS or hypervisor.

10 · OS Kernel Attacks & Privilege Escalation

    
Ring 0 is the whole game: whoever controls the kernel controls everything above it.


    
10.1 Kernel threat vectors

    

      

        
Loadable Kernel Modules (LKMs)

        
Monolithic kernels (e.g. Linux) load device drivers and network protocols dynamically as LKMs. An attacker who inserts a malicious LKM gains unrestricted Ring 0 access to intercept system calls and user processes.

      

      

        
Kernel rootkits

        
Persistent or volatile malicious code installed directly in Ring 0 kernel space. They alter kernel structures (e.g. system call tables), making detection via standard userland utilities impossible — typically requiring a full OS reinstall.

      

    

    
Jailbreaking
Using a kernel privilege-escalation exploit to break an application out of its restricted OS execution sandbox ("jail").


    
10.2 Privilege escalation — two directions

    

      

        
Horizontal escalation

        
Compromise an account, then elevate access to another account at the same privilege level, to harvest that user's distinct assets.

        
User A ══( same level )══▶ User B

      

      

        
Vertical escalation

        
Elevate from a restricted low-privilege account (e.g. web server user www-data) to administrative / root (Ring 0), granting full control of system resources.

        
www-data ──( elevated )──▶ root

      

    


    
10.3 CPU protection rings

    

      
      

        
Ring 0 (most privileged) houses the OS kernel and device drivers.

        
Ring 1 is largely unused on modern systems, historically for device drivers.

        
Ring 3 (least privileged) houses userland applications and unprivileged user processes.

        

          
        

        
Watch the dot climb from Ring 3 into Ring 0 — that is exactly what an exploit like Dirty COW achieves.

      

    


    
10.4 Four primary privilege-escalation pathways

    

      

        
#PathwayDetail

        
          
1Kernel exploitsExploiting kernel vulnerabilities — e.g. Dirty COW (CVE-2016-5195), a Copy-On-Write race condition allowing writes to read-only root files such as /etc/passwd.

          
2Exploiting SUDO rightsMisconfigured /etc/sudoers rules letting standard users execute specific binaries as root.

          
3Exploiting SUID executablesBinaries carrying the Set Owner User ID bit execute with the file owner's (root's) privileges.

          
4User enumerationProbing system configuration and home-directory permissions to find exposed security tokens or credentials.

        
      

    

  


  
  

    
11 · System Software Attacks & Crypto-Virology

    
Attack the shared runtime and you compromise every program that uses it.


    
11.1 Threat mechanisms

    

      
Dynamic linking attacks — LD_PRELOAD

      
On Linux, setting the LD_PRELOAD environment variable forces the dynamic linker to load specified shared objects (.so) before the standard system C library (libc.so). An attacker can therefore intercept any standard function call — read(), write(), open() — and log, alter or suppress it.

    

    

      
Package management attacks

      
Subverting OS package managers (apt, yum) by deploying malicious repository signing keys, creating malicious packages signed with valid keys, or exploiting bugs in the package-manager binary itself.

    

    

      
Ransomware (crypto-virology)

      
Malware that permanently blocks access to victim files by encrypting them with random symmetric/asymmetric key pairs. Advanced ransomware targets backup storage and performs double extortion — exfiltrating data before encryption and threatening public release.

    


    
11.2 Case study — WannaCry

    

      

        
AspectDetail

        
          
Global impactInfected over 200,000 computers across 150+ countries in just 2 days, May 2017.

          
Spread vectorSMB network protocol vulnerability exploited via EternalBlue — self-propagated automatically across enterprise LANs and the internet with no user action (i.e. worm-like behaviour).

          
Ransom mechanismEncrypted victim drives; demanded payment strictly in Bitcoin ($300–$600) to unmonitored crypto-wallets, making payments non-trivial to trace.

          
Root causeMicrosoft patched the SMB flaw in March 2017, but many organisations — including public hospitals — were still running older, unsupported Windows (XP, even Windows 3.0) with no active security updates.

        
      

    

    

      
The exam takeaway

      
WannaCry is a textbook example of worm + ransomware convergence: autonomous propagation combined with destructive cryptographic payload, succeeding largely due to patch-debt on unsupported legacy OS.
