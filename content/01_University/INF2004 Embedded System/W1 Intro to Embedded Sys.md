# What is Embedded System
Computing System that does a specific task INSIDE a machine.

Computer system that is embedded into larger electrical or mechanical system performing SPECIFIC dedicated tasks.

Controller with dedicated function within larger system

Microcontroller -> Minimalist & Embedded
Single-Board Computer -> Compact & Versatile
General-Purpose Computer -> Powerful & Expandable

## Analogue & Digital World
Human world is analogue and continuous, while computer world is digital and discrete

Embedded systems must use a mix of analogue and digital electronics to represent the corresponding signals.


# Properties of embedded system

- Embedded of integral part of a device often hardware parts
- Dedicated to handle specific tasks that are known and assigned to them at design-time
- Uses sensors and actuators to interact with real world
- Have strict timing constraints due to interaction with physical world in safety-critical environment
- Use limited resources compared to general-purpose computer
- Based on microcontrollers

# Compiler / Assembler

### Compiler
- Translate programs written in human-readable language into an equivalent set of opcode for a particular processor
- Cross compiling - Compiling on a host for a target platform
- Native Compiling - Compiling for the same architecture you're running under
- Example: GCC, KEIL, IAR, CCS

### Assembler
- One-to-one translation

# C Runtime Startup Code
Small block of assembly language code that prepares the way for the execution of software written in a high-level language

Most cross-compilers for embedded systems include an assembly language file called `startup.asm` or `crt0.s` 

Typical startup code:
- Disable interrupt
- Copy data into RAM
- Zero uninitialized data area
- Allocate space and initialize the stack
- Create and initialize the heap
- Enable interrupt
- Call main

## Linker
Takes 1 or more object files generated by compiler/assembler and combines them into a single executable file
- Cross-file dependencies are resolved properly, e.g. If you define a variable/function in 1 .c file and use it in another .c file the linker connects the 2 together.
- Link 'reuse' library files; static and dynamic
- Every link is controlled by a linker script, that describes how the executable are mapped onto the memory during execution.

## Integers: Choose the representation deliberately

```C
#include <stdin.h>

uint8_t duty_pct;
int16_t tempertature;
uint32_t tick_count;
```

#### Width
Use `uint8_t`, `int16_t`, `uint32_t` when the number of bits matters

#### Signedness
Use unsigned for bit patterns and non-negative counters.
Use signed for quantities that can be negative

### 3 Common Traps

#### Overflow
```C
uint8_t x = 255;

x++; # this will be 0
```

#### Truncation
```C
uint8_t y = 300; # lower 8 bits retained
```

#### Mixed Arithmetic
Signed and unsigned operands can produce surprising comparisons.

> [!NOTE]
> Treat type selection as part of the hardware interface, not just a coding preference

## Bitwise operations (Change only the intended bits)
![[Pasted image 20260829215447.png]]

```C
#define BIT(n) (1u << (n))

REG |= BIT(3) // set
REG &= ~BIT(3) // clear
REG ^= BIT(3) // toggle
IF (REG & BIT(3)) { /* test */ }
```


### Mask
A '1' selects the bit to operate on.
A '0' leaves the other bits unchanged

### Shift
Move a bit pattern into the field position required by the register

### Parentheses
Make precedence explicit in masks and compound expressions.

> [!NOTE]
> Avoid writing a whole register value when only 1 field should change.


## Qualifiers (Tell the compiler what may change)
```C
volatile bool sampe_ready = false

void ADC_IRQHandler(void) {
	sample_ready = true;
}

while (!sample_ready) { /* wait */}
```

### Const
The program must not modify the object through this name.
Useful for lookup tables and read-only configuration.

### Volatile
The value may change outside normal code flow, such as a hardware register or ISR-shared flag.
Every access must occur as written

### Const volatile
Software reads the value but does not write it. 
Hardware may still update it, such as a status register.

> [!Important Limitation]
> Volatile does not make a multi-step operation atomic. Shared data may still need interrupt masking, atomic operations, or an RTOS synchronization primative.

> Use qualifiers to express access rules, not as a substitute for synchronization.


## Pointers (Connect C objects to memory and peripherals)
```C
#define GPIO_OUT(*(volatile uint32_t *)0x40021000u)

GPIO_OUT |= (1u << LED_PIN);
```
A pointer to a volatile 32-bit unsigned integer at a fixed address

### Firmware pointer checklist
- Correct address and peripheral
- Correct width and alignment
- Volatile for hardware-changing data
- Never dereference an invalid or uninitialized pointer

Wrong pointer = wrong hardware

> A pointer is not merely an address. Its type controls how many bytes are accessed and how they are interpreted.


## Scope, lifetime and linkage (Control who owns state)
Local variable
Scope: 1 block or function 
Lifetime: 1 Call
Best default for temporary state

Static Local
Scope: 1 function
Lifetime: Entire Program
Retrains state between calls

Static file-scope
Scope: 1 source file
Lifetime: Entire program
Hides internal module state

```C
// driver.c
static uint32_t error_count;

uint32_t driver_errors(void) {
	return error_count;
}
```

```C
// driver.h
extern volatile bool driver_ready;

// exactly one .c file defines it
volatile bool driver_ready = false
```

### Alignment
Some processors require or prefer multi-byte values at aligned addresses.
### Packing
Packed structs can remove gaps, but may create slower or invalid unaligned accesses.
### Byte order
Define serialization explicitly for files, buses and network packets. 
Do not transmit raw structs blindly


> Use explicit serialization when data crosses a processor, compiler or communication boundary.
