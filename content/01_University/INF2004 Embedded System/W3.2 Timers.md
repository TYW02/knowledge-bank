# The Software Delay Problem

## Blocking Code
- Functions like `sleep()` or `delay()` are entirely blocking
- CPU is trapped running an empty loop checking the time

## Zero Multitasking
- While **blocked**, the microcontroller **cannot** read sensor data, process inputs, or **respond** to emergencies

# The Gear Reducer: The Prescaler
> Timers require a clock signal to increment. However, system clocks are extremely fast (125 MHz).
> A 16-bit timer counting at 125 MHz overflows in a fraction of a millisecond.

- **The prescaler** mathematically divides the high-frequency system clock before it reaches the timer
- If you set a Prescaler of 125, the actual Timer Register only counts up once for every **125 system clock ticks**, slowing it down to a usable 1 MHz (1 tick = 1 microsecond)

## Timer Config: Up & Down Counting

### Up-Counting (Sawtooth)
> Standard mode.
> The hardware starts at 0, increments to a maximum value, and instantly resets back to 0.
> Example: Stopwatch counting elapsed time up from 0:00

### Down-Counting (Reverse Sawtooth)
> You load a maximum value, and the hardware decrements to 0 before automatically reloading the maximum.
> Example: A microwave timer counting down to 0
![[Pasted image 20260913165333.png]]


## Timer Config: Center-Aligned (Up/Down)

### Up/Down Counting (Center-Aligned)
Instead of snapping back to zero, the timer counts up to MAX, turns around, and gracefully counts back down to 0

### The Triangle Wave
- Creates a perfectly symmetrical triangle wave in hardware

### Why use this ?
- Secret weapon for **Motor Control** and generating **symmetrical PWM** (Pulse Width Modulation)
- Aligns pulses perfectly in the center, which drastically reduces electromagnetic noise and makes motors run smoother.


# When do we get interrupted ?

## Overflow Interrupt
> Fires when the counter hits its absolute limit and rolls over (The peak of the sawtooth)


## Compare Match Interrupt
> Load a specific number into a "Compare Register". As the counter runs, hardware **constantly compares** them. When they **match**, it **fires an interrupt**. This allows triggering events at exact intervals before an overflow happens.

![[Pasted image 20260913170956.png]]


## Input Capture (The Digital Stopwatch)
- While Output Compare creates events, Input Capture **measures external events** with microscopic precision.

### How it works
- GPIO pin is routed directly to a timer.
- When pin changes state (goes HIGH) the hardware instantly copies the timer's current count into a special "Capture Register" and fires an interrupt

### The Analogy
> A runner breaking a laser beam at the finish line. 
> The laser automatically records the exact time on a clipboard before the referee (CPU) reacts

### Use Cases
- Measuring motor RPM
- Decoding IR remote signals
- Reading RC receiver pulse width


# Timer-Triggered DMA (The Invisible Hand)
> Direct Memory Access (DMA) allows data to move around the chip without the CPU lifting a finger. This is the ultimate evolution of non-blocking code

### How it works
> Configure a timer to overflow a specific rate.
> Instead of firing a CPU interrupt, the overflow sends a hardware signal directly to the DMA controller

- DMA grabs 1 sample from the Analog-to-Digital Converter (ADC) and puts it into RAM, entirely independently

### Use Cases
- High-quality audio sampling, reading continuous sensor streams, driving NeoPixels with zero CPU overhead

![[Pasted image 20260913171731.png]]


## Timer Cascading (The Odometer)
> Sometimes, 16-bit timer (up to 65,535) isn't large enough, even with a prescaler, to track time over days or weeks

### How it works
- Hardware timers can be chained together. 
- Timer A counts the system clock. When Timer A overflows, its output is routed as the clock input to Timer B

### The Analogy
> Car odometer. When the "miles" wheel completes a full rotation, it physically clicks the "tens of miles" wheel forward by 1 notch

- This allows creating 32-bit timers out of smaller 16-bit timers

## Dynamic Updates: The Runaway Timer

### The Mistake
Dynamically changing the Compare Match target while the timer is actively running without using Shadow Registers

### The Issue
If the timer is already past the **new** target, it misses the match. It will blindly count all the way to its absolute maximum limit, overflow to zero, and **then** hit the new target

### The Impact
This causes a massive, unexpected glitch in timing, a skipped beat in an RTOS, or a violent stutter in a PWM motor controller.

### The Fix
Always enable Preload/Shadow Registers. The hardware buffers your new value and applies it exactly at the rollover.

# 16-bit Reads on 8-bit Buses: Torn Reads

## The mistake
Reading a multi-byte running timer directly. The CPU has to read the lower half, then the upper half sequentially

## The Issue
If the timer rolls over perfectly in the middle of your 2 reads, you **stitch together** half of the old data and half of the new data

## The Fix
Briefly disable global interrupts, or utilize the hardware's locking mechanism (Many chips automatically freeze the upper byte shadow register the moment you read the lower byte) to ensure an **atomic read**

## Configuration PWM

| Dedicated PWM Peripheral                                 | General-purpose timer PWM                                   |
| -------------------------------------------------------- | ----------------------------------------------------------- |
| Built for richer waveform control                        | Uses timer output-compare behavior                          |
| Multiple synchronized channels and precise update timing | A counter defines position within each PWM period           |
| Often adds complementary outputs and dead-time insertion | A period register defines when the counter rolls over       |
| May include fault/brake inputs for immediate shutdown    | A compare register defines when the output changes state    |
| Best fit: Motor control & Power-conversion stages        | Best fit: LEDs, buzzers, servos, and straightforward driver |
| The exact peripheral name varies by MCU family           | Usually configured as one mode of an ordinary timer         |
> Same mechanism underneath: Clocked counter + Period + Compare + Output Logic
