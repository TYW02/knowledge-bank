# ADC acquires voltage before conversion

1. SELECT (AINSEL chooses GPIO26-29 or temperature sensor)
2. ACQUIRE (Input charges the internal sampling circuitry)
3. CONVERT (Successive approximation resolves 1 bit at a time)
4. PUBLISH (Result updates or the sample enters the FIFO)

## Maximum-rate timing
48 MHz ADC clock, 96 cycles per conversion

## 1 complete result
$2 \mu s$

## Takeaway
> The signal must settle before bit decisions can be trusted


# 12 output bits do not guarantee 12 accurate bits

![[Pasted image 20260913175321.png]]

## The Zero-Crossing Trap
- Nyquist states we must sample at f > 2f
- **Critical Sampling** (exactly 2x) is dangerous in embedded systems
- If sampling perfectly aligns with the signal's zero-crossings, the ADC reads all zeros
- The reconstructed signal appears as a flat DC line (0V), losing the original waveform entirely.

### Solution
Always oversample (2.5x to 3x) and use hardware timers, never software delays to trigger the ADC

## Most "bad ADC" readings begin before the conversion starts
> Diagnose the symptom, then check the electrical cause before rewriting firmware

| Symptom                        | Likely cause                                 | Fix                                                    |
| ------------------------------ | -------------------------------------------- | ------------------------------------------------------ |
| Code wander at rest            | Floating input or noisy reference            | Add a defined source, improve grounding and decoupling |
| First sample is wrong          | Source did not settle after a channel change | Allow settling time, buffer high-impedance source      |
| Waveform has a false frequency | Input bandwidth exceeds the sample plan      | Add an analog low-pass filter, raise sample rate       |
| Readings clip at an endpoint   | Input is outside the valid ADC range         | Scale and protect the input, never exceed ADC_AVDD     |
| Channels influence each other  | Shared converter plus incomplete settling    | Slow the scan, discard a settling sample or buffer     |


## Firmware Calibration

### The Problem
> Silicon is imperfect. Manufacturing tolerances introduce Offset Errors (Curve shifted up/down) and Gain Errors (Slope too steep/shallow)

### Two-point Method
> Calculate true slop and intercept using known low and high voltages

- Gain = $\frac{V_{hi} - V_{lo}}{ADC_{hi} - ADC_{lo}}$
- Offset  = $V_{lo} - (Gain * ADC_{lo})$

### RTOS Implementation
> Execute in a task, not the ISR.
> Use fixed-point math to avoid slow floating-point operations
> $V_{actual} = (ADC * Gain) + Offset$

# RESULT is for polling, FIFO is for continuous capture

## Single Polling Mode
> RESULT register

- Holds the most recent 12-bit conversion result
- Reading RESULT does not clear interrupt flag
- Best matched to manual START_ONCE conversions

## Streaming Mode
> FCS + FIFO register

- The ADC provides an 8-entry FIFO buffer
- FCS controls enable, threshold, underflow, and overflow status
- Reading FIFO removes the oldest 12-but sample
- FIFO decouples the CPU from continuous START_MANY acquisition

> Use RESULT for occasional synchronous reads, use FIFO when samples arrive faster than the CPU should block

# Debug ADC systems by testing 1 uncertainty at a time
1. Known DC
> Apply a safe known voltage and predict the ideal code
2. Repeat
> Capture 1,000 samples, calculate mean, min, max and spread
3. Reference
> Compare ADC_AVDD and ground behavior with a multimeter
4. Timing
> Change sample rate and look for settling or aliasing changes
5. Stress
> Slow the consumer deliberately and observe FIFO OVER
6. Compare
> Measure polling, IRQ, and DMA CPU cost and jitter.

Exit Criterion: You can explain every unexpected code using electrical, timing, or software evidence
