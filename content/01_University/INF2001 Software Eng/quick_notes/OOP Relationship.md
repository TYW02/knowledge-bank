
## Same Core behaviours but unique traits
- Commonalities are grouped into a **Super class** 
- Differences are split into distinct **Sub-Classes**

## Object-Oriented Paradigm
> **Maintainability** increases because the **modular structure** accommodates changes while **protecting** existing code

- Structures software systems as a collection of **Encapsulated** objects
## Class vs Object
- Class is a **program template** defining attributes and behaviours
- Object is a **specific instance** of that template

## Aggregation vs Composition
- They differ in **ownership** & **Lifecycle dependency**

### Aggregation
> [!Definition]
> One object **contains** another, but both have **independent lifecycle**

### Composition
> [!Definition]
> **Strict**, restrictive form of aggregation representing whole-part relationships where the part is **owned exclusively** by the whole.

## Controller Pattern
- Create a Controller class to **mediate** between the two classes


## Information Hiding
- **What** an object does rather than **how** it does it
