title: Doing something that hasn't been done
---
If you are trying to build something that hasn't been done before. You are basically shooting in the dark

# Using Tracer bullets
Tracer bullets are used to help you see if you are hitting your target.

The main goal is to have something built end-to-end so you can get something out to the users and stakeholders. And get feedback from there.

# Difference between Tracer Bullets & Prototype
Usually when you build a prototype, you will most likely re-code everything again after the prototype has been built. 

Whereas with Tracer Bullets, you are building it from end-to-end while adding on top of it after the first feature has been established.
You basically want to give your engineers a structural skeleton to place their code. 

> Build small end-to-end feature to let users see what the final product will look like.
> 
> If good feedback, add more features to it
> 
> Else remove, understand feedback and move in a different direction.
> 
> The code and new features you add are the tracer bullets, users tell you if you are hitting the target.


# Programming Language
Use a language that is closest to what your customers want.

For example, you can use any language that can simulate what you can do and what the customer wants.
It does not have to be an actual programming language, you can just simulate it.
